The "AI Sound Advisor" project (project_master_plan.txt) is built agent-by-agent on the user's "build agent N" requests.

**Workflow the user expects (follow exactly):** write the pytest test file FIRST, run it to confirm the TDD red state (ModuleNotFoundError), then write the implementation, then run the FULL suite and confirm it is 100% green with no regressions.

**Conventions:** Python 3.10, pydantic v2 for structured output models, `from __future__ import annotations`, heavy spec-referencing docstrings, one module per agent under `src/`, tests under `tests/`, classes grouped per component. Hardware/external I/O sits behind an injectable interface (ABC) so everything is tested with in-memory fakes — no real hardware/network. Failsafe orchestration methods must never raise ("System must never crash during service"). The Strategy Pattern is the user's preferred decomposition (Agent 1 analysis strategies, Agent 3 issue detectors).

**Installed deps:** numpy, pydantic, python-osc, pytest, fastapi, uvicorn, httpx (TestClient). NOT installed: scipy, pyloudnorm, librosa — DSP is implemented in pure numpy instead (e.g. real BS.1770 LUFS); sounddevice also not installed (lazy-imported by SoundDeviceAudioSource). Note: fastapi.testclient emits a harmless StarletteDeprecationWarning about httpx — ignore it.

**Progress:** All 7 agents built and green: Agent 1 (`src/audio_analysis.py`), Agent 2 (`src/mixer_state.py`), Agent 3 (`src/detection.py`), Agent 4 (`src/suggestion.py`), Agent 5 (`src/profile_store.py`), Agent 6 (`src/pacing.py`), Agent 7 (`src/interaction.py`). Plus pre-existing core layer: `state_manager.py`, `lifecycle.py`, `setup_assistant.py`. Agent 4 puts the local Mistral 7B (Ollama/LM Studio) behind an injectable `LLMClient` ABC with fallback-to-basic-alerts. Agent 5's `EnvironmentProfile` persists to JSON and emits a `detection.Profile` via `detection_profile()` to feed Agent 3. Agent 6 (`SuggestionPacingAgent.tick(issues, now_ms)`) is deterministic (simulated clock); its `to_suggest` list is what's sent to the LLM. Agent 7 (`UserInteractionAgent`) owns temporary ignore timers and delegates More/Tell-me-how to Agent 4 and mark-normal/instructions to Agent 5.

**System Loop built (`src/system_loop.py`, green):** `SystemLoopOrchestrator.tick(now_ms) -> LoopFrame` runs the 9 spec steps, wiring all 7 agents in order; `run(ticks, interval_ms, start_ms)` drives a simulated clock (no real sleeps). Step 1 "capture audio" is a new injectable `AudioSource` ABC (real impl `SoundDeviceAudioSource`, lazy-imports `sounddevice`), mirroring Agent 2's transport. `tick` NEVER raises: lost audio -> degraded frame with warning + `all_clear=False` (never claims the mix is good when it can't hear); other failures -> safe degraded frame. LLM (Agent 4) is only called with Agent 6's `to_suggest`, enforcing "LLM not every loop". `DEFAULT_LOOP_INTERVAL_MS=250`. NOTE for tests: `low_mid_energy=HIGH` fires BOTH vocal_masking AND eq_mud detectors (co-occur); use clipping metrics for a single-issue scenario.

**Web UI/Dashboard built (`src/web_server.py` + `src/templates/index.html`, green):** FastAPI `create_app(orchestrator, profile_agent, interaction_agent, *, clock=None, ws_interval_ms=300, template_path=None)` wraps the orchestrator; all wiring lives on `app.state` (orchestrator/profile_agent/interaction_agent/clock/suggestion_cache) so tests can inject a deterministic ms clock and swap the orchestrator. Endpoints: `GET /` (serves the dark-mode HTML), `GET /api/state` (runs ONE tick → JSON), `POST /api/mode` + `/api/loudness` (Agent 5, pydantic enum bodies → 422 on bad input), `POST /api/prompt` (Agent 7 handle_prompt), `POST /api/ignore` (Agent 7 ignore, 3-min default; rebuilds an `Issue` with dummy priority/confidence since the ignore key is just (issue,channel)), `WS /ws` (pushes payloads every 300ms). Every endpoint is failsafe (never 500s). The server keeps a presentation cache: it re-attaches the latest generated suggestion text to currently-active issues so the panel stays stable between pacing/LLM ticks (no extra LLM calls). Frontend is plain HTML/CSS/JS (no jinja2), WebSocket-primary with HTTP-poll fallback. Production entry: `uvicorn src.web_server:build_default_app --factory` (uses SoundDeviceAudioSource + UdpOscTransport + the real LLM client below when configured). `build_default_app(config=None)` reads a `ServerConfig.from_env()` (pydantic model, defensive parsing — invalid ints fall back to defaults) so the X32 IP and audio device are env-configurable, no code edits: `SOUND_ADVISOR_X32_IP` (default 192.168.0.2 = `DEFAULT_X32_IP`), `_X32_PORT` (10023), `_OSC_TIMEOUT` (1.0), `_AUDIO_DEVICE` (int index OR device-name string), `_SAMPLE_RATE` (48000), `_AUDIO_CHANNELS` (1), `_PROFILE_DIR` ("profiles"). `SoundDeviceAudioSource.device` now accepts int|str. Also `run_dashboard.py` (repo root) is a hardware-free DEMO launcher wiring fakes that cycle clean->clipping->masking every ~6s. 252 tests passing.

**Real LLM client built (`src/llm_client.py`, green):** Concrete HTTP backends for Agent 4 behind an injectable `HttpTransport` ABC (default `UrllibHttpTransport`, stdlib only — no new dep; tests inject a `FakeTransport`, no network). `OllamaLLMClient` (POST `/api/generate`, health `/api/tags`) and `LMStudioLLMClient` (POST `/chat/completions`, health `/models`) both implement the existing `src.suggestion.LLMClient` ABC, so they drop into `SuggestionGenerator(client)`. `generate()` raises `LLMUnavailableError` (RuntimeError subclass) on any failure (connection/timeout/HTTP/JSON/bad-shape/empty) so SuggestionGenerator's `except Exception` still falls back to basic alerts; `is_available()` is a never-raising health probe for the dashboard's AI/LLM status indicator. Env-driven `LLMConfig.from_env()` + `build_llm_client()` select the backend: `SOUND_ADVISOR_LLM_BACKEND` (none|ollama|lmstudio, default **none** → returns None → basic alerts; unknown value safely → none), `_LLM_MODEL`, `_LLM_BASE_URL`, `_LLM_TIMEOUT` (invalid → 30.0). `build_default_app` now calls `SuggestionGenerator(build_llm_client())` so the model is wired purely from env, no code edits. REFACTOR: the old inline `OllamaClient`/`LMStudioClient` drafts were REMOVED from `suggestion.py` (superseded by llm_client.py); the `LLMClient` ABC + `DEFAULT_SYSTEM_PROMPT` stay in suggestion.py to avoid an import cycle (llm_client imports from suggestion, never the reverse). 281 tests passing.

**V2 feature pass built (326 tests passing, all green):** Implemented the remaining master-plan gaps in High→Low order, test-first.
- **Agent 7 actions wired to UI:** `POST /api/more`, `/api/tellmehow`, `/api/mark-normal` (shared `IssueActionRequest` {issue, channel}; `_issue_from()` rebuilds a dummy-priority Issue like /api/ignore). All failsafe. UI: More / Tell me how / Mark normal / Ignore buttons per suggestion + a persistent `#detail-panel` (lives OUTSIDE the auto-refreshing `#suggestions-list` so detail survives the ~300ms re-render).
- **Logging System (`src/event_log.py`):** `LogSink` ABC + `InMemoryLogSink` + `JsonlFileSink` (newline-delimited JSON, skips corrupt lines on read). `SessionLogger(sink, metrics_interval_ms=5000)` with `log_issue/log_user_action/log_metrics/log_event/log_frame/records/recent`. `log_frame` dedups issues (logs ISSUE_DETECTED once on appearance, ISSUE_RESOLVED on clear) and throttles METRICS to ≤1 per interval. Fully failsafe (broken sink never raises). Wired as optional `event_logger=` on `SystemLoopOrchestrator` (logs every tick via `_log_frame_safe`) and `create_app` (logs user actions via `_log_action`; `GET /api/log/recent?limit=` review endpoint). `build_default_app` wires `JsonlFileSink(log_dir/"session.jsonl")`; `ServerConfig.log_dir` from `SOUND_ADVISOR_LOG_DIR` (default "logs").
- **AI/LLM availability:** `SuggestionGenerator.llm_available()` (None client→False; client with is_available→probe; else True). `LoopFrame.llm_available: Optional[bool]`. Orchestrator `_refresh_llm_available()` CACHES the probe — re-probes only every `LLM_PROBE_INTERVAL_MS=5000` (honours "LLM not every loop"). UI: 4th status dot `#ai-dot`.
- **Calibration:** `POST /api/calibrate` runs a tick, calls `profile_agent.calibrate(frame.metrics)` (fails safe if metrics None). `LoopFrame.calibrated` from `_safe_calibrated()`. UI: "Capture good mix" button + status.
- **End-of-event save:** `GET /api/profile/summary` (has_unsaved_changes + pending_changes), `POST /api/profile/save` (save() → ok:false failsafe when storage_dir is None, e.g. in_memory agent). UI: "Review & save profile" panel.
- **Focus Mode:** server-side presentation flag `app.state.focus_mode`; `POST /api/focus {enabled}`; `_tick_payload` adds `focus_mode` and `_apply_focus` trims issues+suggestions to `[:1]` (frame already sorted highest-priority-first). UI: checkbox toggle.
- **Automatic change detection:** orchestrator `_detect_user_changes(mixer, metrics, now_ms)` compares prev tick — fader move ≥`CHANGE_FADER_DB=1.0` or mute toggle → `pacing.notify_user_change(channel=name)`; loudness jump ≥`CHANGE_LOUDNESS_LUFS=3.0` → global pause. First tick never triggers. Failsafe.

- **Recording/Broadcast Analysis module (`src/recording_analysis.py`, green):** Strategy Pattern like Agents 1/3. `RecordingComparator` ABC + three default comparators (`LoudnessImbalanceComparator` thr `LOUDNESS_IMBALANCE_LUFS=3.0`/HIGH≥6; `VocalClarityComparator` = recording high_freq LOWER than room; `MixInconsistencyComparator` = low_mid mismatch). `RecordingAnalysisEngine([...]).analyze(room, recording)` → `RecordingAnalysis(available, findings[severity-sorted], room_metrics, recording_metrics, all_clear property)`. Each `RecordingFinding{kind: RecordingFindingType, severity: detection.Priority, confidence, message}` carries its own instructor-tone message (no LLM needed). Failsafe (broken comparator skipped). Wired into the loop via a SECOND injectable `recording_source: AudioSource` + `recording_analysis_engine` on `SystemLoopOrchestrator`; `_analyze_recording(room_metrics, warnings)` captures the feed with the SAME `self._audio_engine` (Agent 1) and compares vs room. `LoopFrame.recording: Optional[RecordingAnalysis]` (None when no feed; `available=False` + `RECORDING_LOST_WARNING` on capture failure — room loop unaffected). Web: payload carries `recording` (degraded payload → None), UI `#recording-panel` ("Broadcast / Recording"). `ServerConfig.recording_device` from `SOUND_ADVISOR_RECORDING_DEVICE` (int|str); `build_default_app` only wires the recorder `SoundDeviceAudioSource` + engine when set. `run_dashboard.py` demos it (DemoRecordingSource tags its buffer with `np.ones` so DemoAudioEngine returns a deliberately quieter+dull broadcast → shows loudness_imbalance + vocal_clarity findings; only the zero-buffer room capture advances the state cycle). **350 tests passing.**

NOTE: this repo lives in Dropbox; the Edit tool leaves stray `src/*.tmp.*` / `tests/*.tmp.*` atomic-write artifacts (Dropbox blocks the rename). Clean them with `rm -f src/*.tmp.* tests/*.tmp.*` after editing.

All master-plan modules are now built. Possible future refinements (not gaps): separate room-mic vs main-mix inputs (currently the primary `audio_source` is the room reference and the recorder feed is the second input); log rotation.

**UI/UX enhancement pass (361 tests passing):** Four dashboard improvements, test-first.
- **Per-card embedded detail:** removed the shared `#detail-panel`; More/Tell-me-how now expand an embedded `.card-detail` inside each suggestion card. Because `#suggestions-list` re-renders every ~300ms, open detail is kept in a JS `detailState` map keyed by `issue|channel` and re-applied on every `renderSuggestions(lastState)`; clicking the same button again closes it; entries for cleared issues are pruned.
- **Real LLM chat:** `SuggestionGenerator.chat(message, history, mix_summary) -> (text, source)` (reuses `_invoke` → LLM when available, else `_chat_fallback`); `UserInteractionAgent.chat(...)` delegates (does NOT mutate the profile — `handle_prompt` is still the learning path). `POST /api/chat {message, history:[{role,content}]}` grounds the reply via `_mix_summary(app)` (from `orchestrator.last_frame`) and returns `{reply, source}`, failsafe. Old `/api/prompt` kept. UI: prompt panel → "AI CHAT" panel with a multi-turn bubble log (`chatHistory`), pending "…" placeholder, fallback-styled bot bubbles.
- **Tab-split broadcast:** the suggestions panel has `#main-tabs` (Suggestions / Broadcast) with live counts; recording findings moved into `#broadcast-list` (separate bottom `#recording-panel` removed). `renderBroadcast` replaces `renderRecording`.
- **Channel names everywhere:** each card shows a `.chip.channel` = the channel label where one applies, else "Main mix". Backend: `SuggestionGenerator._target` now returns "the main mix" (was "the channel") for channel-less issues. (Only `vocal_masking` carries a real channel; clipping/loudness/eq are mix-wide by design.)
- Frontend now HTML-escapes all interpolated text via `escapeHtml`. NOTE: the page-content test now asserts "chat" (not "prompt") in the markup.
